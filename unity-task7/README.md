# Задание 7 Интерактивный Unity WebAR

Продолжение настоящего Unity-проекта из `downloads/unity-task6-source.zip`.
Проект рассчитан на Unity **6000.3.7f1** и Built-in Render Pipeline. Камеры,
WebXR Export **0.25.0**, материалы и подготовка сборки сохранены из задания 6.

Добавлены XRI **2.6.4**, Input System **1.11.2** и встроенная адаптированная копия
`com.someone-s.webxr-xrit-bridge` **0.1.2-task7.1**. Версия XRI 2.x выбрана для
совместимости с API исходного bridge; обновление на XRI 3.x потребует изменений кода.

**Статус:** исходники подготовлены. JavaScript-тесты проходят. В среде подготовки
нет Unity Editor: C# ещё не скомпилирован, сборка задания 7 не выполнена и на
устройстве не проверена. `unity-viewer/` по-прежнему содержит сборку задания 6.
Это не подтверждение выполнения последнего требования задания до сборки и теста.

## Быстрый запуск на Windows

1. Установить Unity 6000.3.7f1 с Web Build Support через Unity Hub; нужна рабочая
   лицензия Unity. Добавить **папку `unity-task7`**, а не корень сайта, в Hub.
2. Дождаться восстановления пакетов. При предложении перезапуска для включения
   Input System согласиться. Active Input Handling уже задан как Input System.
3. Выполнить **WebAR → Prepare task 7 scene**, затем нажать Play. В Game view
   можно перетаскивать куб мышью и масштабировать колесом во время захвата.
   Исходная сцена ViewerSpace из задания 6 служит основой; без Prepare task 7
   она всё ещё содержит старое поведение. Новая сцена — `Assets/Scenes/InteractiveAR.unity`.
4. Для WebGL закрыть проект в редакторе и запустить PowerShell из `unity-task7`:

```powershell
powershell -ExecutionPolicy Bypass -File .\Build.ps1 -CopyToSite
```

Скрипт вызывает `WebAR.Task7.Editor.BuildTask7.Build`, сам подготавливает сцену,
проверяет код возврата Unity, файлы WASM, JS жестов, метрики и маркер успешной сборки.
Полный лог — `build.log`. Результат — `Build/WebGL/`, а с `-CopyToSite` он также
копируется в `../unity-interactive/`. Скрипт ничего не отправляет на GitHub.

При другом пути к редактору:

```powershell
.\Build.ps1 -UnityEditor 'D:\Unity\6000.3.7f1\Editor\Unity.exe' -CopyToSite
```

Альтернатива из Unity: **WebAR → Build task 7 WebGL**. Подготовка пересоздаёт
учебные сцену и prefab в этой копии проекта; ручные изменения сохраните отдельно.

## Управление

- На телефоне коснуться **самого куба**, удерживать и двигать палец. Луч
  `XRRayInteractor` захватывает `XRGrabInteractable` через `XRInteractionManager`.
- Добавить второй палец и раздвигать/сводить пальцы для pinch. Первый палец
  продолжает управлять лучом, второй меняет масштаб. Диапазон — 40–300% от
  исходного размера (сторона куба 0,06–0,45 м; исходно 0,15 м).
- Если первым отпущен управляющий палец, захват завершится. Отпустить остальные
  пальцы и начать новый жест: объект не перескакивает к оставшемуся пальцу.
- `−` и `+` позволяют менять масштаб без pinch; **Сброс** возвращает куб на 0,65 м
  перед текущей камерой, восстанавливает размер и завершает захват.
- В настольном браузере работают наведение, перетаскивание левой кнопкой мыши и
  кнопки масштаба. В Unity Game view масштаб во время захвата меняется колесом.
- При наличии WebXR-контроллеров: навести видимый луч, удерживать trigger и
  перемещать контроллер; thumbstick Y меняет масштаб во время захвата.
- Обычный куб золотистый, при наведении голубой, при захвате зелёный с эмиссией.

В отличие от задания 6, куб не перепривязывается к камере каждый кадр и не вращается
самостоятельно. Он появляется перед камерой при старте/сбросе и после отпускания
остаётся в `local` reference space. Поиск поверхности и привязка к столу не реализуются:
для задания 7 достаточно интерактивного объекта в пространстве AR.

## Что подключено

`Assets/Editor/BuildTask7.cs` вызывает подготовку задания 6, удаляет
`ViewerSpaceCube`, отделяет куб от камеры, добавляет Rigidbody без гравитации,
XRGrabInteractable, менеджер и три XRRayInteractor: экранный, левый и правый.

`ScreenRayController` превращает нормализованные координаты DOM Overlay в
`XRControllerState`, учитывая проекцию **активной AR-камеры** через
`ViewportPointToRay`. Это не перенос HTML-картинки: модель остаётся объектом Unity,
выбор и перемещение выполняет XRI. `Task7SceneController` управляет ограниченным
масштабом, цветовым откликом и сбросом. Масштабирование отключено в стандартном
XRI grab transformer, чтобы он не перезаписывал результат pinch.

`webxr-xrit-bridge` преобразует WebXR-позы, tracking, trigger, grip и thumbstick
в два устройства Input System. `ActionBasedController` считывает их действия и
управляет лучами. `BridgeRayGate` блокирует взаимодействие непроверенного tracking
и читает ось масштаба. Устройства удаляются при отключении адаптера.

Оригинальный bridge 0.1.2 предназначен прежде всего для VR и не подходит к этому
проекту без изменений: в WebXR 0.25 изменена сигнатура OnHeadsetUpdate, старый
headset adapter создаёт собственные камеры, а типы симулятора XRI 2.6 могут
исключаться из WebGL через ENABLE_VR. Поэтому используется **модифицированный
встроенный пакет**, с исходной лицензией и описанием изменений в
`Packages/com.someone-s.webxr-xrit-bridge/PATCHES.md`. Старый headset adapter и
prefab сохранены в `Upstream~` и не импортируются Unity. Камерами управляет
работавший в задании 6 WebXRCamera.

В `webxr.jspre` добавлена поддержка DOM Overlay при наличии `#task7-overlay`.
В AR требуются `local` и `dom-overlay`; касания считываются прозрачной HTML-областью
над XR-изображением. `beforexrselect` подавляет дублирующий native select.
`SendMessage` передаёт ввод в C#, а небольшой `.jslib` возвращает статус и масштаб.
Потеря указателя, смена размера окна, скрытие страницы, переход/завершение AR и
сброс прекращают жест. Отказ запуска AR возвращает Unity в обычный режим.

## Публикация после успешной сборки

После `Build.ps1 -CopyToSite` добавить **всю** папку `unity-interactive/` в ветку
`codex/github-pages` и отправить изменения. После обновления GitHub Pages сборка
будет доступна по адресу:

https://fancybear01.github.io/webar-mindar/unity-interactive/

Этот адрес не является готовой сборкой, пока файлы задания 7 не собраны и не
опубликованы. Старые `unity-viewer/` и `downloads/unity-task6-source.zip` не заменяются.
Сжатие отключено, специальные Content-Encoding заголовки не нужны.

Для временной проверки до публикации, из папки проекта:

```powershell
python -m http.server 8082 --directory Build/WebGL
```

В другом окне:

```powershell
cloudflared tunnel --url http://localhost:8082
```

Открыть выданную **HTTPS**-ссылку на телефоне. Простого HTTP по IP ноутбука
недостаточно для WebXR. Совместимые Android, Chrome и ARCore обязательны;
DOM Overlay тоже должен поддерживаться браузером.

## Проверка перед сдачей

Из корня репозитория выполнить тесты JavaScript (Node 18+):

```sh
node tools/check_task7.mjs
```

Они проверяют жесты, переходы от двух пальцев к одному, отмену, наведение,
реальную функцию запроса сессии с подставным WebXR API, неизменность исходных
настроек, DOM Overlay и восстановление после отказа. Они **не** запускают Unity,
не проверяют XRGrabInteractable и не заменяют тест мобильного AR.

В Unity запустить **WebAR → Validate task 7 scene**, собрать WebGL и убедиться,
что в `build.log` есть `TASK7_SCENE_VALIDATED` и `TASK7_BUILD_SUCCESS`.
Затем на настоящем телефоне выполнить все проверки:

1. Открыть HTTPS-страницу, дождаться Unity, нажать «Начать AR», разрешить камеру.
   За кубом должно быть изображение реальной комнаты.
2. Коснуться куба: он становится зелёным. Провести пальцем: куб перемещается.
3. Добавить второй палец: размер меняется плавно и ограничивается 40–300%.
   После отпускания второго пальца drag продолжается без скачка.
4. Первым отпустить управляющий палец: захват прекращается без перескока объекта.
5. Отпустить всё и переместить телефон: куб сохраняет позицию в пространстве.
6. Нажать `+`, `−`, «Сброс»: интерфейс работает в AR и не вызывает захват лучом.
7. Свернуть/вернуть браузер, повернуть экран, выйти и снова войти в AR:
   захват не остаётся активным, куб доступен после сброса.
8. Если есть контроллеры: проверить оба луча, trigger, thumbstick и отключение
   контроллера во время захвата. При отсутствии контроллеров отметить «нет устройства».

В отчёт занести модель телефона, Android, Chrome, результат каждого шага и
скриншоты камеры с подсветкой и изменённым размером. Сейчас эти результаты не
измерены. `build-metrics.json` создаётся только при успешной сборке и сохраняет
статус мобильной проверки `pending real device`.
